🚀 Schnellstart-Anleitung (für Eilige)

  1. Stelle sicher, dass Python 3.8+ installiert ist.
  2. Führe pip install -r requirements.txt aus.
  3. Führe python launcher.py aus, um die config.json zu erstellen.
  4. Trage deinen Discord Bot Token und ein sicheres Passwort in die config.json ein.
  5. Aktiviere alle Privileged Gateway Intents für deinen Bot im Discord Developer Portal.
  6. Starte den Bot erneut mit python launcher.py.
  7. Greife lokal auf das Dashboard zu via http://127.0.0.1:5000.

1. Kernphilosophie & Technologie-Stack

Dieses Framework wurde nach drei Kernprinzipien entwickelt, um maximale Stabilität, Sicherheit und Erweiterbarkeit zu gewährleisten.

  • Vollständige Modularität: Jede Funktion ist ein "Plugin" (Cog). Ein Plugin kann einfach durch Hinzufügen oder Entfernen seines Ordners (de-)aktiviert werden.
  • Strikte Datentrennung: Der Bot-Kern (`bot.py`, `webapp.py`) ist strikt von den Daten getrennt. Der Kern hat seine eigene Datenbank (`database/bot_main.db`), und jedes Plugin ist dafür verantwortlich, seine eigenen Daten in einem dedizierten Ordner (`plugin_data/PluginName/`) zu verwalten.
  • Nahtlose & sichere Web-Integration: Jedes Plugin kann seine eigenen Webseiten und API-Routen zum zentralen Web-Dashboard hinzufügen, ohne den Kern-Code zu verändern.

Technologie-Stack

  • Bot-Framework: Python 3.8+ mit discord.py
  • Web-Framework: Flask für das Dashboard und die Plugin-Webseiten.
  • Datenbank: SQLite3 für eine einfache, dateibasierte Speicherung.
  • Prozess-Management: Ein nativer Python subprocess-Launcher.

2. Installation & Erstkonfiguration

Eine schrittweise Anleitung zur Inbetriebnahme des Bots.

  1. Abhängigkeiten installieren: Führe pip install -r requirements.txt aus.
  2. Discord Bot einrichten (WICHTIG):
    • Gehe zum Discord Developer Portal und erstelle eine neue Anwendung.
    • Gehe zum Tab **"Bot"**, klicke **"Add Bot"** und dann **"Reset Token"**, um deinen Token zu kopieren. Behandle diesen Token wie ein Passwort!
    • Aktiviere unter **"Privileged Gateway Intents"** alle drei Schalter (Presence, Server Members, Message Content). Ohne diese wird der Bot nicht starten.
    • Gehe zu **"OAuth2" -> "URL Generator"**, wähle `bot` und `applications.commands` aus, gib dem Bot `Administrator`-Rechte und lade ihn mit dem generierten Link auf deine Server ein.
  3. Bot erstmalig starten: Führe python launcher.py aus. Eine config.json und alle Daten-Ordner werden automatisch erstellt.
  4. Konfigurieren: Öffne die config.json und trage deinen **Bot-Token** und ein sicheres **Dashboard-Passwort** ein.
  5. Test-Server ID eintragen: Trage unter development_guild_id die ID deines Haupt- oder Test-Servers ein. Dies ist entscheidend für den lokalen Admin-Zugriff und den schnellen Befehls-Sync im Entwicklungsmodus.

Troubleshooting bei der Installation

  • Fehler `PrivilegedIntentsRequired`: Du hast die Intents im Developer Portal nicht aktiviert (siehe Schritt 2.3).
  • Slash-Befehle erscheinen nicht: Entweder bist du im Produktionsmodus und musst bis zu einer Stunde warten, oder die `development_guild_id` ist falsch.
  • `403 Forbidden` im Dashboard: Du versuchst als externer Benutzer auf eine Admin-Seite zuzugreifen. Nutze den lokalen Admin-Login.

3. Das Web-Dashboard: Ein Benutzerhandbuch

Das Zwei-Wege-Login-System erklärt

Der Zugriff auf das Dashboard ist dual geregelt:

  • Lokaler Admin-Zugriff: Wenn du das Dashboard von demselben Rechner aus aufrufst, auf dem der Bot läuft (über http://127.0.0.1:5000), wirst du zu einer Passwort-Login-Seite geleitet. Nach der Eingabe des Passworts aus der config.json bist du als **lokaler Admin** eingeloggt und hast vollen Zugriff auf alle Funktionen.
  • Externer Benutzer-Zugriff: Greift jemand von außerhalb auf die URL zu, muss die Authentifizierung zwingend über Discord erfolgen. Ein direkter Aufruf der Seiten ist nicht möglich. Externe Benutzer müssen über das /accesspanel in Discord einen sicheren Einmal-Link anfordern und haben nur Zugriff auf die Plugins, für die sie explizit freigeschaltet wurden.

Seiten-Übersicht & Funktionen

Dashboard
Die Hauptseite zeigt Echtzeit-Statistiken über den Bot und die Systemauslastung.
Plugins
Zeigt eine Liste aller erfolgreich geladenen Plugins (Cogs).
Berechtigungen
Eine Admin-Seite zur Verwaltung der Zugriffsrechte auf private Web-Plugins für externe Benutzer.
Konfiguration
Eine Admin-Seite zur Änderung von globalen Bot-Einstellungen.
Status
Ändere den Online-Status und die Aktivität des Bots. Diese Einstellung wird in der Datenbank gespeichert.
Server-Browser
In der linken Seitenleiste werden alle Server aufgelistet. Ein Klick auf einen Server zeigt dessen Kanäle an.

Tutorial: Berechtigungen verwalten

Diese Seite ist das Herzstück der Zugriffsverwaltung und nur für lokale Admins sichtbar.

  1. Server-Auswahl: Wähle oben rechts aus dem Dropdown-Menü den Discord-Server aus. Die Seite lädt neu.
  2. Rechte hinzufügen: Wähle für ein Plugin "Rolle" oder "Benutzer", wähle die Entität aus der Liste und klicke auf "Hinzufügen".
  3. Rechte entfernen: Klicke auf das Mülleimer-Icon neben einem Eintrag.
Pro-Tipp: Verwalte Rechte bevorzugt über Rollen statt über einzelne Benutzer. Das ist bei größeren Servern deutlich übersichtlicher.

4. Befehls-Referenz (Alle Plugins)

Alle Bot-Befehle werden durch Plugins bereitgestellt.

Access Panel Plugin

Dieses Kern-Plugin verwaltet den sicheren Web-Zugriff für externe Benutzer.

BefehlBeschreibungBerechtigung
/accesspanel create Erstellt ein Panel in einem Kanal mit Buttons für jedes private Web-Tool. Benutzer klicken hier, um ihren persönlichen "Magic Link" anzufordern. Admin

Verification Plugin

Ein mehrstufiges Verifizierungssystem, um Mitglieder zu authentifizieren.

BefehlBeschreibungBerechtigung
/verifypanel create Erstellt das Verifizierungs-Panel in einem Kanal. Admin
/verifyconfig level Setzt das Sicherheitslevel (1-4). Admin
/verifyconfig role Legt die Rolle fest, die Mitglieder nach der Verifizierung erhalten. Admin
/verifyconfig joinrole Legt die Rolle fest, die Mitglieder beim Betreten erhalten. Admin
/verifyconfig removerole Legt die Rolle fest, die nach der Verifizierung entfernt wird. Admin
/unverify Hebt die Verifizierung eines Mitglieds auf. Admin

5. Entwickler-Handbuch: Eigene Plugins erstellen

Die Anatomie eines modernen Plugins

Ein Plugin ist ein Ordner in cogs/, der alle seine Komponenten bündelt: cog.py (Discord-Logik), optional eine web.py (Web-Logik) und einen templates/-Ordner. Der Bot findet und lädt diese automatisch.

Wichtige Entwickler-Konzepte

  • Datenbanken: Jedes Plugin sollte seine eigene SQLite-DB in plugin_data/PLUGINNAME/ erstellen und verwalten.
  • Web-Plugins (Öffentlich vs. Privat): Standardmäßig ist jede Plugin-Webseite privat. Um eine Seite öffentlich zu machen, füge blueprint.is_public = True in die web.py ein.
  • Slash-Befehle (Dev vs. Prod): In der config.json steuert "clear_commands_on_startup" das Verhalten. true für sofortige Updates auf dem Test-Server, false für globale Updates (bis zu 1h Verzögerung).

6. Glossar

Cog / Plugin
Eine in sich geschlossene Funktionserweiterung für den Bot, die in einem eigenen Ordner unter cogs/ lebt.
Blueprint
Ein modulares Web-Modul von Flask. In diesem Projekt enthält jede web.py eines Plugins ein Blueprint, das dem Haupt-Webserver neue Seiten hinzufügt.
Session
Eine temporäre, serverseitige Speicherung von Benutzerdaten im Webserver, z.B. ob ein Benutzer eingeloggt ist. Sie wird durch ein Cookie im Browser des Benutzers identifiziert.
Token (Auth-Token)
Ein sicherer, zufälliger und zeitlich begrenzter Code, der vom Bot in Discord erstellt wird, um einem Benutzer einen einmaligen Login auf der Webseite zu ermöglichen.
